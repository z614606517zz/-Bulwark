VirusTotal 多 Key 与提额

VT 支持一次配多个 Key,用英文逗号分隔。 每个 Key 独立计账、额度叠加;某个 Key 触发限流(429)或失效(401)会自动冷却并跳到下一个。 还可按 KEY:每日上限:每分钟上限 标注,便于混用免费与 Premium。

Architecture
🏗

三层协作架构

驱动 ↔ 服务经 Filter Manager 通信端口对话,服务 ↔ UI 经命名管道对话。 无论事件来自哪个事件源,统一由一个 RuleEngine 作决策中心。

内核态驱动 R0

Minifilter 驱动 Bulwark.sys,做「行为发生前」原地拦截:硬拦名单、受保护项、 网络黑名单、自我保护。六个监控维度分别由 ProcessMonitor FileMonitor RegistryMonitor NetMonitor ImageMonitor ThreadMonitor 实现, SelfProtect 负责自保,Comms 负责与服务通信。

用户态服务 R3

bulwark_service.exe 承载全部决策与处置逻辑:Worker 主防御循环 (事件 → 富化 → 引擎 → 裁决 → 处置),EventSourceCoordinator 合并 ETW、用户态持续行为源与热切换的内核源;隔离区、足迹清理、持久化存储、SCM 集成都在这一层。

桌面 UI Qt Widgets

bulwark_ui.exe,10 个功能页:仪表盘、拦截记录、活动日志、防护规则、信任名单、 隔离区、自启动项、云信誉、AI 研判、设置。另有行为弹窗、角标通知、扫描进度、 清理报告与攻击时间线等对话框。

⚠
项目状态如实说明: 内核驱动尚未在真实内核里做过端到端验证。Bulwark.sys 必须在带快照的测试虚拟机里 开启测试签名并加载,才能真正启用「行为发生前」内核拦截;内核回调出错可能蓝屏。 默认发布产物跑的是 ETW 用户态观测链路,用户态(R3 + UI)可直接编译运行。

两种可切换的事件源

Decision Pipeline
⚖️

决策流水线 RuleEngine

每个事件进入 RuleEngine::evaluate 后按固定优先级走一条流水线,命中即返回 —— 而不是简单的三选一。

  1. 无条件放行 —— 本软件自身组件;用户明确信任的文件 / 文件夹(信任 = 完全跳过后续一切检测)Allow
  2. 已安装的知名安全软件 —— 共存放行,避免互相残杀Allow
  3. 威胁研判 —— ThreatDetector 计算风险分并置位「硬恶意指标」
  4. 有状态时序检测 —— 勒索行为、C2 信标、DGA 域名、外联速率;触碰蜜罐诱饵直接阻止Block
  5. 行为基线偏离(可开关) —— 显著偏离程序自身历史画像时产出软信号,须与硬指标互证才升格
  6. 显式规则 —— 按「层级 > 具体度 > 动作强度 > 最近创建」排序命中
  7. 强可信主体 —— 证书指纹白名单,或微软签名 + 系统目录,且签名健康、无危险行为Allow
  8. 签名异常 —— 证书被吊销 / 用过期证书签名Block
  9. 健康签名 —— 排除硬指标与「空壳新证书」画像后放行Allow
  10. 仅当存在硬恶意指标才处置 —— 风险分 ≥ 高危阈值则阻止,否则弹窗询问BlockAsk
  11. 无硬指标 → 一律放行 —— 仅记录。软信号绝不单独定罪Allow
✓
裁决完成后自动追加「最终裁决」证据, 并由 AttackAnnotator 统一标注 MITRE ATT&CK 技战术。裁决动作为 Allow / Block / Ask,来源标记为:命中规则 / 行为研判 / 可信放行 / 用户裁决 / 超时默认 / 默认策略。
Detection
🔬

检测能力

威胁研判中心 ThreatDetector 汇总内置启发式并调度多个专项分析器, 每条命中都写入结构化证据(硬指标 / 软信号 / 互证 / 信任 / 规则 / 信息)。

内置启发式

  • 签名校验失配、证书被吊销、过期证书签名
  • 首见 + 空壳新证书画像
  • 超大未签名文件(文件膨胀规避扫描)
  • 可疑目录运行:Temp / Public / ProgramData / Downloads / Roaming / Desktop
  • Windows 非标准子目录伪装
  • 异常父子链:Office / 浏览器派生 LOLBin(疑似宏病毒、钓鱼)
  • 进程伪装:系统进程名出现在合法目录之外(T1036.005)
  • 形近仿冒:svch0st / 1sass / 西里尔字母(编辑距离 ≤ 1)
  • 双重扩展名(T1036.007)、NTFS 备用数据流执行(T1564.004)
  • 覆盖大量 ATT&CK 技战术的命令行特征表
-enc 编码命令DownloadString IEX 动态执行mimikatz / sekurlsa comsvcs.dllvssadmin delete

专项分析器

  • LOLBins 白利用 —— regsvr32 / rundll32 / mshta / certutil / bitsadmin / msbuild / wmic / comsvcs 被「二进制 + 特征参数」滥用(Squiblydoo、远程 HTA、certutil 下载、 comsvcs 转储 LSASS)。高置信滥用作硬指标,并让签名信任豁免失效 —— 签名可信 ≠ 行为可信。
  • 凭据访问 —— LSASS 转储 / 注入、SAM / SECURITY 蜂巢导出、NTDS.dit 提取、 浏览器凭据库 / DPAPI 读取
  • 防御规避 —— 篡改 Defender、AMSI / ETW 致盲、清空事件日志、关防火墙 / UAC
  • 远控 / RMM 滥用 —— RDP 劫持、反弹 shell,及即时通讯群控注入 / 侧载
  • 进程注入 / DLL 侧载 —— 跨进程远程线程、可写目录加载未签名模块
  • 命令行混淆(无特征码) —— 香农熵、符号占比、超长 Base64 块的统计研判
  • 脚本内容静态分析 —— PowerShell / VBS / JS / Batch 脚本体
  • 杀伤链阶段分析 —— 同一进程树覆盖 ≥3 个 ATT&CK 阶段才计分

有状态时序监视器

按 PID / 序列维护滑动窗口,线程安全。

  • 勒索行为 —— 批量改写速率、扩展名同化、勒索信写入、蜜罐诱饵触碰(命中即阻止)
  • C2 信标 —— 按 (PID | 远端) 记录外联时序,用周期性与抖动(变异系数)识别回连
  • 外联速率 / 扇出 —— 速率突发与目标扇出,软信号需互证
  • DGA 域名 —— 只看字符串统计特征(熵 / 元音比 / 连续辅音 / 数字交错),无黑名单
  • 行为基线 —— 为每个程序建立子进程 / 外联 / 写目录画像,带学习期,可导入导出快照
  • 进程链关联 —— 串起孤立事件,识别 dropper,支持整树足迹清理

信任策略分级 TrustPolicy

  • 知名安全软件共存
  • 强可信(可跳过行为检测)
  • 健康签名
  • 较可信签名(仅风险打折)
  • 可豁免敏感规则的 OS 组件
⚠
任一档下出现危险命令行、 LOLBin 滥用、凭据攻击或签名异常,一律不再放行。

AI 研判(大模型)

OpenAI 兼容接口,异步,任何失败都 fail-open。三种能力:

  • 基于纯静态内容特征研判恶意性 —— 绝不执行样本
  • 把自然语言安全意图转成 1~5 条可复核的防御规则
  • 对恶意 / 可疑文件一键生成清理脚本

静态特征由 StaticFeatureExtractor 越界安全地提取:PE 头 + 各节香农熵(判壳,熵 > 7.2)、 危险 Win32 API / URL / IP 字符串、能力标签(注入 / 反调试 / 键盘钩子 / 加密勒索 / 提权……)。

AI 灰区策略

仅对「询问(Ask)」类灰区事件咨询大模型: AI 判恶意则升格阻止;AI 判干净且无硬指标则降级放行(减少打扰);其余维持原判。

✓
AI 绝不压制硬指标,也绝不改判确定性拦截或强可信放行。
Response
🧹

处置、隔离与足迹清理

拦截

内核源在动作前原地拒绝; 用户态观测源无法事前拦截,由 Worker 事后结束作恶进程树补偿,带关键进程防护。

隔离区

确认恶意的载荷经 XOR 中和后拷入金库, 删除原文件(被占用则计划重启删除),完全可逆还原。

足迹清理

ThreatRemediator 按进程树 清理恶意足迹;PersistenceScanner 只读枚举 7 类自启动持久化点。

Design Principles
🎯

设计原则

只对真正危险的行为动手

软信号(未签名、可疑路径、首见、新证书) 永远不单独触发拦截或弹窗,只加分,并且必须与硬指标互证才升格。

尽量不打扰

健康签名的正规程序默认放行, 不弹窗。误报和骚扰本身就是安全软件最大的可用性问题。

自我保护可控

这是一个正当的安全工具: 始终保留正常的、用户主导的卸载路径,绝不做成「卸不掉」。
