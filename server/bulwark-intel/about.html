使用方法

配置文件是 bulwark_service.exe 同目录下的 appsettings.json; 在 UI 里改的设置存到 %ProgramData%\Bulwark\settings.json。 两者冲突时以 UI 里的选择为准 —— appsettings.json 只提供部署初值。

第一次跑起来:其实就一件事

解压(密码 123),然后 双击 启动Bulwark.bat —— 它会自动提权,并自己判断该做什么。 脚本全程幂等:每一步都先查状态,已经做好的直接跳过。所以第一次运行 = 安装 + 启动, 以后每次运行 = 只是启动,不需要记住自己上次做到哪一步。

  1. 信任随包驱动的签名证书 —— 导入 LocalMachine 的 Root 与 TrustedPublisher
  2. 体检 Secure Boot / HVCI —— 这两项开着,测试签名一定无效
  3. 开启测试签名 —— bcdedit,需重启一次。重启前会问你「重启后自动继续吗」, 选 Y 就不用再管,登录后自动接着装完
  4. 复制 Bulwark.sys —— 到 %SystemRoot%\System32\drivers\
  5. 以 Minifilter 语义注册服务 —— type=filesys + FltMgr 依赖 + Instances\DefaultInstance + Altitude=385201 + Flags=0
  6. fltmc load 加载并验证
  7. 拉起后台服务与界面 —— 便携模式下,关掉界面就一起收摊
ℹ
想只看状态不动系统:启动Bulwark.bat -Check。 它只体检、不改动任何东西,逐项列出「装到哪一步了、当前是内核前拦截还是用户态观测」, 每条失败都写明该怎么办。卸载:双击 卸载.bat。

两种事件源怎么选

  • Wmi —— 纯 ETW 用户态观测(取值名沿用历史命名)。不加载驱动、不需要测试签名、不会蓝屏。 无法事前拦截,靠事后结束作恶进程树补偿。日常先用这个。
  • Driver —— 加载 Minifilter,硬拦名单 / 受保护项 / 网络黑名单 / 自我保护在动作发生前原地拒绝; 进程创建走「遥测 + 启动后结束」补偿模型。
✓
内核里有一份自足基线。 硬拦名单、进程禁运名单、被封禁主体的子进程拒绝、自我保护、本地已知恶意 SHA-256 集合 全部在内核内判定 —— 用户态服务没在跑,这些照样生效。热路径从不做同步 IPC。

弹窗怎么处理

日常最主要的交互就这一个框。

  • 三个选择:允许 / 阻止 / 记住这次选择(把裁决落成一条规则,以后同样行为不再问)
  • 有超时:PromptTimeoutSeconds 默认 30 秒,超时走 DefaultAction(默认 Allow)
  • 只有灰区且存在硬恶意指标才会弹。未签名、可疑路径、首见、新证书这类软信号单独出现时不弹
ℹ
超时兜底刻意不下发内核持久禁运名单 —— 你离开键盘一会儿,不该让某个程序被永久拦死。

加白:信任文件 / 文件夹

这是整页最容易误解的一处,值得单独读一遍。

  • 在「信任名单」里加白 = 流水线第 1 步无条件放行,跳过后面全部检测 —— 含云信誉、VT、AI 与时序检测
  • 批量部署用 TrustedDirectories 预置整目录,语义与在 UI 里手动加白一个文件夹完全相同
  • 它在第 1 步、规则在第 7 步 —— 所以你写的「阻止」规则盖不住加白
⚠
加白是本软件里最强的一条放行通道, 只信任你确实清楚来源的东西。

规则能盖住什么

  • 命中排序:层级 > 具体度 > 动作强度 > 最近创建
  • 盖不住第 1~3 步:自身组件与用户信任项、已安装的第三方安全软件、知名 IM 客户端的网络与 DNS 事件
  • 举例:给某个 IM 写「禁止外联」不会生效(第 3 步已放行);但对它的其他行为 —— 侧载、群控模块加载 —— 规则照常生效,因为第 3 步只对网络 / DNS 那两类事件开口
  • 也可以在 UI 里用自然语言让 AI 生成 1~5 条规则,生成后需你复核采纳,不会自动上线

云查毒与情报共享

  • ReputationProxy 指向本站:不填自己的 Key 也能用上聚合信誉,由服务端持有上游密钥; 任何失败自动回退本地直连,防护不退化
  • LookupOnly 管服务端要不要去问它的付费上游 —— true = 只查它库里已收录的
  • ServerOnly 管本机要不要用自己的密钥直连第三方 —— true 时本机一个第三方源都不动, 也绝不上传文件到 VT;代价是服务器没收录的文件就没有云端结论
  • 两者是不同的两条轴,别搞混
🔐
回传只含结论本身(哈希 / 判定 / 引擎计数 / 威胁名), 不含文件内容、不含路径、不含机器标识。「威胁情报共享」总开关在设置界面,默认关闭; 开启后每天在 ContributionUploadHour 整点上传(带 0~5 分钟错峰)。

攻击链组合引擎

纯查表,无模型无训练。服务器从每日样本沙箱记录里 数出「哪几个动作凑在一起就足以定性」,客户端下载组合表并给每个进程记账,凑齐即作为硬指标喂给裁决流水线。

  • DryRun=true —— 只记录不影响裁决
  • MinGrade —— hard(仅最强)/ strong / ask(全部)
  • 端点留空则复用 ReputationProxy 的地址(同一台服务器)
⚠
组合特征来自纯恶意样本库,没有正常文件作对照。 务必先用 DryRun=true 在真机跑几天、确认没冤枉正常软件,再转入强制。

自我保护与卸载

  • 自我保护挡的是外部进程对本软件文件 / 注册表 / 进程的篡改
  • 可配 ProtectedPaths(默认含启动文件夹与 hosts)、 ProtectedRegistryKeys(默认含 Run / RunOnce)、 MemoryProtectionTargets(默认 lsass.exe,防凭据转储)
  • UI 客户端除映像路径校验外,还可用 UiClientAllowedPublishers 追加签名发布者约束
✓
始终保留正常卸载路径: 在 UI 里关闭自我保护 → 停止服务 → 正常卸载。这是设计原则,绝不做成「卸不掉」。

排查常见问题

  • 界面连不上服务 —— bulwark_ui.exe 不在安装目录内会被拒连,放回原目录
  • 没有任何拦截 —— 服务没启动,或没以管理员身份运行,ETW 与驱动链路都起不来
  • 选了 Driver 却没有事前拦截 —— 驱动加载失败会回落到 ETW 观测,此时只有事后补偿
  • 填了 Key 不生效 —— 服务以 SYSTEM 运行时读不到用户级环境变量,须设为系统级
  • 某程序被反复拦 —— 先看事件记录里的证据链和裁决来源,再决定是加规则还是加白

内核驱动怎么加载

启动Bulwark.bat 已经把这一整套自动做完了,这一节是讲它到底做了什么、 为什么必须做、以及哪一步没做成会怎样。想手动核对或排查时看这里。

为什么必须有「安装」这一步

Bulwark.sys 是内核模块, 不可能从桌面文件夹里直接跑起来。它必须先满足四个条件:

  • 签名证书被本机信任 —— 随包驱动用自签测试证书 CN=BulwarkTestCert, 导入 Root 与 TrustedPublisher
  • 系统开启测试签名 —— bcdedit /set testsigning on,要重启一次
  • 文件放进 %SystemRoot%\System32\drivers\
  • 以 Minifilter 语义注册 —— type=filesys + FltMgr 依赖 + Instances\DefaultInstance + Altitude=385201 + Flags=0
⚠
少了最后那一步的 Instances / Altitude, 驱动不会附加到卷,文件与注册表回调一个都不会触发 —— 服务能连上内核端口、界面一切正常,但什么都拦不到。 这就是为什么不能把它当普通 kernel 服务用 sc create type= kernel 注册。

没装会怎样

防护照样能开,界面也正常 —— 但事件源会静默降级为用户态观测,只能事后终止进程,拦不住「行为发生前」。

  • 驱动连不上时日志写:「内核驱动暂不可用,已降级为用户态观测,后台将持续重试。」, 之后每 10 秒自愈重试一次,恢复后写「内核驱动连接已恢复。」
  • 找不到 .sys 时写:「未找到 Bulwark.sys,无法注册内核驱动(将降级为用户态观测)。」
  • 端口连不上时写:「无法连接内核驱动端口(驱动未加载 / 无管理员权限 / 测试签名未开?)」
ℹ
这种失败从界面上看不出来, 所以启动脚本每次都会把当前形态明确打出来 —— 别只看「防护已开启」就以为内核拦截生效了。

前置条件:不满足则一定加载不了

  • Secure Boot 必须关闭 —— 开着时测试签名完全无效,bcdedit 那一步会被引导策略拒绝
  • 内存完整性(HVCI)必须关闭 —— Windows 安全中心 > 设备安全性 > 内核隔离
  • x64 + Windows 10 1703 或更新 —— 覆盖 1703 ~ 22H2、LTSC 2019 与全部 Win11; 构建期有导入表护栏,防止用到新版 DDI 导致老系统上 0xC0000139 加载失败
✓
这两项脚本会自动检查 (Confirm-SecureBootUEFI 与 Win32_DeviceGuard)并告诉你去哪里关, 不用自己猜为什么加载不上。
⚠
严重警告: 内核驱动的回调里一旦出错就是直接蓝屏(BSOD)。首次务必在带快照的测试虚拟机里验证; 要在真机上跑,请先建系统还原点。

便携模式 vs 常驻模式

  • 默认(便携) —— 启动Bulwark.bat 拉起服务和驱动,关掉界面就一起收摊。 干净,但关掉就没有防护。
  • 常驻 —— 启动Bulwark.bat -InstallService 把用户态服务注册为开机自启。 此后不要再用 启动Bulwark.bat 托管服务(会另起一个实例抢同一条控制管道), 直接双击 bulwark_ui.exe 即可。
  • -BootStart 让驱动开机随系统加载,消除「重启后服务先于驱动起来 → 降级用户态 → 勒索漏拦」的防护空窗。

确认驱动真的挂上了

除了 -Check,也可以自己核对。 关键是看 fltmc filters 里有没有 Bulwark 以及 Altitude 对不对 —— 只看 sc query 是 RUNNING 不足以说明它附加到卷了。

管理员命令提示符
> fltmc filters

Filter Name        Num Instances    Altitude    Frame
-----------------  -------------  ------------  -----
Bulwark                        3      385201      0     <- 挂上了

> sc query Bulwark
        STATE              : 4  RUNNING
  • 两个服务名别搞混:Bulwark 是内核 Minifilter, BulwarkService 是用户态服务(刻意区分,避免冲突)
  • 用户态通过 \BulwarkPort 连接内核并做协议握手,连接失败会重试 5 次约 1.5 秒
  • 看内核日志:DebugView,勾选 Capture Kernel
  • 升级驱动的正确顺序:停服务 → fltmc unload Bulwark → 覆盖 .sys → 启动服务

出问题了:双击 收集日志.bat

把排查需要的东西一次性打包成桌面上的一个 zip。 它只读,拿不到管理员权限就降级采集并明确告诉你少了哪部分 —— 服务起不来、甚至提权都有问题时也能跑。

  • 已替你脱敏:信誉代理端点、所有 API 密钥、Bearer 令牌 (service.log 里确实会出现端点地址,所以这步是必要的); Windows 用户名替换成 <用户名>,路径结构保留
  • 刻意没收:隔离区里的文件内容(那是真实恶意样本,打包会被别的杀软拦下, 也等于在传播样本,只给文件名和大小清单)、audit\ 与 history\ 的全量数据(上百 MB,只取最新一个文件的尾部)、内核转储 MEMORY.DMP
⚠
日志里仍会包含你机器上的进程命令行和文件路径 —— 这是排障必须的,但发到公开论坛前建议自己扫一眼,介意的话改成私发。 压缩包里的 _必读.txt 写了同样的说明。

卸载得干净

这是正经安全工具,始终保留用户自主卸载的通路, 不存在「装上就删不掉」。卸载.bat 单独放在外面、不藏在参数后面,就是这个原因。 默认一次做完全套,不用记任何参数:

  1. 停掉界面和后台服务
  2. 卸载内核驱动 —— fltmc unload
  3. 删除两个服务注册 —— Bulwark 内核服务 + BulwarkService 用户态服务
  4. 删除 System32\drivers\Bulwark.sys
  5. 移除 BulwarkTestCert —— 从「受信任的根证书颁发机构」和「受信任的发布者」
  6. 退出测试模式 —— bcdedit /set testsigning off,重启后右下角水印消失
  7. 清掉「重启后自动继续」和安装标记
  8. 问一句要不要删数据目录(默认保留)
  9. 复查一遍并列出残留
✓
最后会重新读一遍真实状态。有残留就直说是哪几项 —— 几乎都是「文件还被内核占着」,重启一次再跑一遍就干净了。

卸载里两处刻意的设计

  • 测试签名是「机器全局」开关。安装时会记一笔「这是本产品打开的,还是本来就开着」。 如果是你自己为别的自签名驱动开的,卸载不会去关它,只会告诉你手动关的命令 —— 否则会把你那个驱动一起弄得加载不了,而且没人会想到是卸载干的。 没有安装记录时(老版本装的)按关闭处理,并在屏幕上说明怎么再打开。
  • 数据目录默认保留。%ProgramData%\Bulwark 里有你攒下的规则、审计日志, 以及隔离区里的真实恶意样本。删掉不可恢复,所以只问一句。 无人值守地删用 -PurgeData,明确要留用 -KeepData。

在线威胁分析台用法

你正在看的这个站点就是本项目的云端信誉后端 —— 客户端 ReputationProxy 查的就是它。 它同时提供网页分析台,不装客户端也能直接用。

查一个哈希

  • 搜索框粘 MD5 / SHA-1 / SHA-256,回车即得多源聚合结论:判定、检出比、家族、类型、各情报源结论
  • 恶意与可疑样本的报告永久缓存,重复查询极快;安全文件不缓存

拖一个文件进来

  • SHA-256 在你自己的浏览器里算,默认只把哈希发出去 —— 文件本身不动
  • 本地算哈希依赖 crypto.subtle,必须在 HTTPS 下才可用
  • 确实要整文件送检时才会上传,那是一次显式操作
页面看什么
威胁档案已收录的恶意样本报告库,可按家族 / 类型 / 时间检索
银狐情报针对该攻击团伙的专项跟踪
正常样本白样本库。经复检确认干净的样本单独成区 —— 用来量误报、给行为基线做对照
攻击链引擎当前下发给客户端的动作组合表,以及每条组合背后的样本证据数
在线客户端已接入客户端概览

HTTP API

每个请求都要带 Key:请求头 X-API-Key (也支持 Authorization: Bearer <key> 或 ?key=)。 Key 向管理员申请,每个 Key 有每分钟 / 每天调用上限。

# 哈希信誉摘要(多源:判定 / 检出比 / 家族 / 类型 / 各源结论)
curl -H "X-API-Key: KEY" https://vt.bulwark.icu:8787/api/v1/hash/<sha256>

# 完整报告:逐引擎检测 + 沙箱行为 + 多源情报(原始 JSON)

Architecture
🏗

三层协作架构

驱动 ↔ 服务经 Filter Manager 通信端口对话,服务 ↔ UI 经命名管道对话。 无论事件来自哪个事件源,统一由一个 RuleEngine 作决策中心。

内核态驱动 R0

Minifilter 驱动 Bulwark.sys,做「行为发生前」原地拦截:硬拦名单、受保护项、 网络黑名单、自我保护。六个监控维度分别由 ProcessMonitor FileMonitor RegistryMonitor NetMonitor ImageMonitor ThreadMonitor 实现, SelfProtect 负责自保,Comms 负责与服务通信。

用户态服务 R3

bulwark_service.exe 承载全部决策与处置逻辑:Worker 主防御循环 (事件 → 富化 → 引擎 → 裁决 → 处置),EventSourceCoordinator 合并 ETW、用户态持续行为源与热切换的内核源;隔离区、足迹清理、持久化存储、SCM 集成都在这一层。

桌面 UI Qt Widgets

bulwark_ui.exe,11 个功能页:仪表盘、事件记录、事件时间线、攻击链、进程管理、 防护规则、信任名单、隔离区、自启动项、云信誉、设置。另有行为弹窗、角标通知、 扫描进度、清理报告、AI 清理向导与攻击时间线等对话框。

⚠
项目状态如实说明: 内核驱动尚未在真实内核里做过端到端验证。Bulwark.sys 必须在带快照的测试虚拟机里 开启测试签名并加载,才能真正启用「行为发生前」内核拦截;内核回调出错可能蓝屏。 默认发布产物跑的是 ETW 用户态观测链路,用户态(R3 + UI)可直接编译运行。

Decision Pipeline
⚖️

决策流水线 RuleEngine

每个事件进入 RuleEngine::evaluate 后按固定优先级走一条流水线,命中即返回 —— 而不是简单的三选一。

  1. 无条件放行 —— 本软件自身组件;用户明确信任的文件 / 文件夹(信任 = 完全跳过后续一切检测)Allow
  2. 已安装的知名安全软件 —— 共存放行,避免互相残杀Allow
  3. 已知良性厂商应用 —— 仅限网络 / DNS 事件。即时通讯客户端的保活心跳周期性极强, 会被信标检测当成 C2 回连,所以在这一步先放掉。刻意只对这两类事件开口:一旦扩大到其他事件类型, 针对 IM 侧载、群控模块加载的规则就会被一并绕过Allow
  4. 威胁研判 —— ThreatDetector 计算风险分并置位「硬恶意指标」
  5. 有状态时序检测 —— 勒索行为、C2 信标、DGA 域名、外联速率;触碰蜜罐诱饵直接阻止Block
  6. 行为基线偏离(可开关) —— 显著偏离程序自身历史画像时产出软信号,须与硬指标互证才升格
  7. 显式规则 —— 按「层级 > 具体度 > 动作强度 > 最近创建」排序命中
  8. 强可信主体 —— 证书指纹白名单,或微软签名 + 系统目录,且签名健康、无危险行为Allow
  9. 签名异常 —— 证书被吊销 / 用过期证书签名Block
  10. 健康签名 —— 排除硬指标与「空壳新证书」画像后放行Allow
  11. 仅当存在硬恶意指标才处置 —— 风险分 ≥ 高危阈值则阻止,否则弹窗询问BlockAsk
  12. 无硬指标 → 一律放行 —— 仅记录。软信号绝不单独定罪Allow
⚠
这条流水线是有顺序的,不是三选一 —— 顺序本身就是行为。 显式规则在第 7 步才被检查,所以一条「阻止」规则盖不住第 1~3 步:本软件自身组件与你手动信任的 文件 / 文件夹、已安装的第三方安全软件、以及知名 IM 客户端的网络 / DNS 事件。 规则怎么写都不生效时,先去信任名单里找一找。
✓
裁决完成后自动追加「最终裁决」证据, 并由 AttackAnnotator 统一标注 MITRE ATT&CK 技战术。裁决动作为 Allow / Block / Ask,来源标记为:命中规则 / 行为研判 / 可信放行 / 用户裁决 / 超时默认 / 默认策略。
Detection
🔬

检测能力

威胁研判中心 ThreatDetector 汇总内置启发式并调度多个专项分析器, 每条命中都写入结构化证据(硬指标 / 软信号 / 互证 / 信任 / 规则 / 信息)。

内置启发式

  • 签名校验失配、证书被吊销、过期证书签名
  • 首见 + 空壳新证书画像
  • 超大未签名文件(文件膨胀规避扫描)
  • 可疑目录运行:Temp / Public / ProgramData / Downloads / Roaming / Desktop
  • Windows 非标准子目录伪装
  • 异常父子链:Office / 浏览器派生 LOLBin(疑似宏病毒、钓鱼)
  • 进程伪装:系统进程名出现在合法目录之外(T1036.005)
  • 形近仿冒:svch0st / 1sass / 西里尔字母(编辑距离 ≤ 1)
  • 双重扩展名(T1036.007)、NTFS 备用数据流执行(T1564.004)
  • 覆盖大量 ATT&CK 技战术的命令行特征表
-enc 编码命令DownloadString IEX 动态执行mimikatz / sekurlsa comsvcs.dllvssadmin delete

专项分析器

  • LOLBins 白利用 —— regsvr32 / rundll32 / mshta / certutil / bitsadmin / msbuild / wmic / comsvcs 被「二进制 + 特征参数」滥用(Squiblydoo、远程 HTA、certutil 下载、 comsvcs 转储 LSASS)。高置信滥用作硬指标,并让签名信任豁免失效 —— 签名可信 ≠ 行为可信。
  • 凭据访问 —— LSASS 转储 / 注入、SAM / SECURITY 蜂巢导出、NTDS.dit 提取、 浏览器凭据库 / DPAPI 读取
  • 防御规避 —— 篡改 Defender、AMSI / ETW 致盲、清空事件日志、关防火墙 / UAC
  • 远控 / RMM 滥用 —— RDP 劫持、反弹 shell,及即时通讯群控注入 / 侧载
  • 进程注入 / DLL 侧载 —— 跨进程远程线程、可写目录加载未签名模块
  • 命令行混淆(无特征码) —— 香农熵、符号占比、超长 Base64 块的统计研判
  • 脚本内容静态分析 —— PowerShell / VBS / JS / Batch 脚本体
  • 杀伤链阶段分析 —— 同一进程树覆盖 ≥3 个 ATT&CK 阶段才计分

有状态时序监视器

按 PID / 序列维护滑动窗口,线程安全。

  • 勒索行为 —— 批量改写速率、扩展名同化、勒索信写入、蜜罐诱饵触碰(命中即阻止)
  • C2 信标 —— 按 (PID | 远端) 记录外联时序,用周期性与抖动(变异系数)识别回连
  • 外联速率 / 扇出 —— 速率突发与目标扇出,软信号需互证
  • DGA 域名 —— 只看字符串统计特征(熵 / 元音比 / 连续辅音 / 数字交错),无黑名单
  • 行为基线 —— 为每个程序建立子进程 / 外联 / 写目录画像,带学习期,可导入导出快照
  • 进程链关联 —— 串起孤立事件,识别 dropper,支持整树足迹清理

信任策略分级 TrustPolicy

  • 知名安全软件共存
  • 强可信(可跳过行为检测)
  • 健康签名
  • 较可信签名(仅风险打折)
  • 可豁免敏感规则的 OS 组件
⚠
任一档下出现危险命令行、 LOLBin 滥用、凭据攻击或签名异常,一律不再放行。

Response
🧹

处置、隔离与足迹清理

拦截

内核源在动作前原地拒绝; 用户态观测源无法事前拦截,由 Worker 事后结束作恶进程树补偿,带关键进程防护。

隔离区

确认恶意的载荷经 XOR 中和后拷入金库, 删除原文件(被占用则计划重启删除),完全可逆还原。

足迹清理

ThreatRemediator 按进程树 清理恶意足迹;PersistenceScanner 只读枚举 7 类自启动持久化点。

Design Principles
🎯

设计原则

只对真正危险的行为动手

软信号(未签名、可疑路径、首见、新证书) 永远不单独触发拦截或弹窗,只加分,并且必须与硬指标互证才升格。

尽量不打扰

健康签名的正规程序默认放行, 不弹窗。误报和骚扰本身就是安全软件最大的可用性问题。

自我保护可控

这是一个正当的安全工具: 始终保留正常的、用户主导的卸载路径,绝不做成「卸不掉」。
