磐垒主动防御 (Bulwark HIPS) — 便携包使用说明
================================================================

■ 就一件事:双击  启动Bulwark.bat

  它会自己判断该做什么,已经做好的步骤直接跳过:

    信任驱动签名证书 → 体检 Secure Boot / HVCI → 开启测试签名
    → 复制 .sys 到 System32\drivers → 注册 Minifilter
    → 加载驱动 → 启动后台服务 → 打开界面

  第一次运行 = 安装 + 启动,会要求重启一次(开测试签名必须重启)。
  重启前它会问你「重启后自动继续吗」,选 Y 就不用再管,登录后自动接着装完。
  以后每次运行 = 只是启动。

  卸载:双击  卸载.bat


■ 需要看状态时

    启动Bulwark.bat -Check

  只体检、不改动任何东西。会把「装到哪一步了、当前是内核前拦截还是
  用户态观测」逐项列出来,每条失败都写明该怎么办。


■ 出问题了:双击  收集日志.bat

  把排查需要的东西一次性打包成桌面上的一个 zip,发出来就行,不用再来回
  追问「日志在哪」「什么系统」「装了什么杀软」。

  包里是:体检报告、系统与环境信息(含已安装的其他安全软件、服务与驱动
  状态、事件日志里与本产品相关的记录)、运行期日志、脱敏后的配置。

  已经替你处理掉的:
    · 信誉代理端点、所有 API 密钥、Bearer 令牌
      —— service.log 里确实会出现端点地址,所以这步是必要的,不是形式
    · Windows 用户名(替换成 <用户名>,路径结构保留)

  刻意没有收的:
    · 隔离区里的文件内容。那是真实恶意样本,打包会被别的杀软拦下,
      也等于在传播样本。只给文件名和大小清单。
    · audit\ 与 history\ 的全量数据。整个数据目录上百 MB,当附件不现实,
      只取最新一个文件的尾部;其余留清单,需要时再单独索取。
    · 内核转储 MEMORY.DMP / Minidump。太大,蓝屏排查时再单独索取。

  日志里仍会包含你机器上的进程命令行和文件路径 —— 这是排障必须的,
  但发到公开论坛前建议自己扫一眼,介意的话改成私发。
  压缩包里的 _必读.txt 写了同样的说明。

  服务起不来、甚至提权都有问题时也能跑:它是只读的,拿不到管理员权限
  就降级采集并明确告诉你少了哪部分。


■ 为什么必须有这一步安装

  Bulwark.sys 是内核模块,不可能从桌面文件夹里直接跑起来。它必须先:

    · 签名证书被本机信任(随包驱动用自签测试证书 CN=BulwarkTestCert)
    · 系统开启测试签名模式(bcdedit /set testsigning on,要重启一次)
    · 文件放进 %SystemRoot%\System32\drivers\
    · 以 Minifilter 语义注册(type=filesys + FltMgr 依赖 +
      Instances\DefaultInstance + Altitude=385201 + Flags=0)

  少了最后那一步的 Instances/Altitude,驱动不会附加到卷,文件和注册表
  回调一个都不会触发 —— 服务能连上内核端口,但什么都拦不到。

  没装会怎样?防护【照样能开】,界面也正常 —— 但事件源静默降级为用户态
  观测,只能事后终止进程,拦不住「行为前」。这种失败从界面上看不出来,
  所以启动脚本每次都会把当前形态明确打出来。


■ 前置条件(不满足则驱动一定加载不了)

  · Secure Boot 必须【关闭】       —— 开着时测试签名完全无效
  · 内存完整性 (HVCI) 必须【关闭】 —— Windows 安全中心 > 设备安全性 > 内核隔离

  这两项脚本会自动检查并告诉你去哪里关。


■ 严重警告

  内核驱动的回调里一旦出错就是直接蓝屏 (BSOD)。首次务必在【带快照的
  测试虚拟机】里验证;要在真机上跑,请先建系统还原点。


■ 便携模式 vs 常驻模式

  默认(便携):启动Bulwark.bat 拉起服务和驱动,关掉界面就一起收摊。
               干净,但关掉就没有防护。

  常驻:  启动Bulwark.bat -InstallService
          把用户态服务注册为开机自启。此后【不要】再用 启动Bulwark.bat
          托管服务(会另起一个实例抢同一条控制管道),直接双击
          bulwark_ui.exe 即可。

  另外 -BootStart 可让驱动开机随系统加载,消除「重启后服务先于驱动
  起来 → 降级用户态 → 勒索漏拦」的防护空窗。


■ 全部可用参数

    启动Bulwark.bat                    默认:缺哪步补哪步,然后启动
    启动Bulwark.bat -Check             只体检,不改动
    启动Bulwark.bat -SetupOnly         只安装,不启动服务和界面
    启动Bulwark.bat -BootStart         驱动改为开机随系统加载
    启动Bulwark.bat -InstallService    服务注册为开机自启(常驻)
    收集日志.bat                       打包诊断信息到桌面 zip(自动脱敏)
    卸载.bat                           完整卸载(见下节,默认就做全套)
    卸载.bat -PurgeData                连规则/日志/隔离区一起删,不再询问
    卸载.bat -KeepData                 不询问,直接保留数据目录
    卸载.bat -KeepTestSigning          保留测试签名开启状态
    卸载.bat -KeepCert                 保留 BulwarkTestCert 证书

■ 卸载得干净:双击  卸载.bat

  这是正经安全工具,始终保留用户自主卸载的通路,不存在「装上就删不掉」。
  卸载.bat 单独放在外面、不藏在参数后面,就是这个原因。

  默认一次做完全套,不用记任何参数:

    1. 停掉界面和后台服务
    2. 卸载内核驱动(fltmc unload)
    3. 删除两个服务注册(Bulwark 内核服务 + BulwarkService 用户态服务)
    4. 删除 System32\drivers\Bulwark.sys
    5. 从「受信任的根证书颁发机构」和「受信任的发布者」移除 BulwarkTestCert
    6. 退出测试模式(bcdedit /set testsigning off)—— 重启后右下角水印消失
    7. 清掉「重启后自动继续」和安装标记
    8. 问一句要不要删数据目录(默认保留)
    9. 复查一遍并列出残留

  最后会重新读一遍真实状态。有残留就直说是哪几项 —— 几乎都是「文件还被
  内核占着」,重启一次再跑一遍就干净了。

  关于第 6 步(测试签名是【机器全局】开关):
    安装时会记一笔「测试签名是本产品打开的,还是本来就开着」。如果是你
    自己为别的自签名驱动开的,卸载不会去关它,只会告诉你手动关的命令 ——
    否则会把你那个驱动一起弄得加载不了,而且没人会想到是卸载干的。
    没有安装记录时(老版本装的)按关闭处理,并在屏幕上说明怎么再打开。

  关于第 8 步(数据目录):
    %ProgramData%\Bulwark 里有你攒下的规则、审计日志,以及隔离区里的
    【真实恶意样本】。删掉不可恢复,所以默认保留、只问一句。
    要无人值守地删:卸载.bat -PurgeData;明确要留:卸载.bat -KeepData。


■ 数据与日志位置

  %ProgramData%\Bulwark\
    bootstrap-status.txt   上次自举的人类可读记录(起不来时先看这个)
    service.log            后台服务主日志(轮转为 service.log.1)
    crash.log              崩溃记录
    rules.json             生效的规则
    audit\ history\        审计与事件历史(体积最大的两块)
    quarantine\            隔离区(真实样本,收集日志时刻意不打包)

  不想手动翻这些:双击 收集日志.bat,它会挑好、脱敏并打包。

  内核日志:DebugView,勾选 Capture Kernel。
