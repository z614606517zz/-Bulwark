磐垒主动防御 (Bulwark HIPS) 1.0.3 —— 说明
================================================================

■ 安装

  双击 Bulwark-Setup-1.0.3.exe,按向导走完即可(会弹一次 UAC 管理员授权)。

  向导做的事:
    欢迎 → 风险须知(要勾「我同意」)→ 选择安装位置 → 附加任务
    → 准备安装(这一页会明确写出内核驱动会被怎么处置)→ 安装
    → 完成(可勾选立即运行)

  装完即用:界面驻留系统托盘,关窗口不会停止防护,开机自动运行。


■ 「附加任务」页上那两个跟内核驱动有关的选项

  · 开启测试签名模式
      只有本机还没开启时才会出现。勾了它安装程序会执行
      bcdedit /set testsigning on,需要重启一次才生效;重启后后台服务会自己把
      内核驱动加载上来,不需要再跑一遍安装程序。
      这是【机器全局的启动设置】,代价写在风险须知里。卸载时只会关掉本产品自己
      开的那一次 —— 如果它在安装之前就是开着的,卸载不会去动它。

  · 内核驱动随系统启动加载
      默认是「按需加载」(后台服务启动时加载)。勾上它改成开机随系统加载,消除
      「开机后到服务起来之前」那段几秒钟的防护空窗。代价是驱动更早介入启动过程。


■ 内核驱动什么情况下会自动加载

  随包的 Bulwark.sys 用【自签测试证书 CN=BulwarkTestCert】签名。64 位 Windows
  的内核代码签名策略要求内核模块带受认可的签名,自签证书不满足,唯一例外是系统
  处于测试签名模式。所以:

    已开启测试签名  → 部署 + 注册 + 立即加载,拿到【行为前拦截】
    未开启测试签名  → 仍然部署好并注册好,但不加载

  第二种情况下防护【照样是开着的】,只是降级为用户态强制:能事后终止进程、能挡
  出站连接、能挡再次启动,但拦不住「行为发生之前」那一刻。这种降级从界面上一眼
  看不出来,所以「准备安装」页会先讲明,安装完的日志也会写明,界面设置页里还会
  如实列出「生效 N/13 个维度」以及哪几项没生效。

  两个硬前提(不满足则一定加载不了):
    · Secure Boot 必须【关闭】       —— 开着时测试签名完全无效
    · 内存完整性 (HVCI) 必须【关闭】 —— Windows 安全中心 > 设备安全性 > 内核隔离


■ 严重警告

  内核驱动的回调里一旦出错就是直接蓝屏 (BSOD)。首次务必在【带快照的测试虚拟机】
  里验证;要在真机上跑,请先建系统还原点。


■ 卸载

  开始菜单 > 磐垒主动防御 > 卸载
  或:设置 > 应用 > 已安装的应用 > 磐垒主动防御 > 卸载

  这是正经安全工具,始终保留用户自主卸载的通路,不存在「装上就删不掉」。
  卸载会依次:停界面 → 停后台服务 → 卸内核驱动 → 删两个服务注册 → 删
  System32\drivers\Bulwark.sys → 移除本产品导入的 BulwarkTestCert → 关闭本产品
  开启的测试签名 → 清各用户的登录自启项 → 问一句数据目录 → 删程序文件 → 复查
  并如实列出残留。

  残留几乎都是「文件还被内核占着」:重启一次再卸一遍就干净了。

  数据目录 %ProgramData%\Bulwark(自定义规则、审计日志、隔离区里的真实样本)
  默认【保留】,卸载时会单独弹框问一次 —— 删掉不可恢复。


■ 装完之后怎么确认真实状态

  开始菜单 > 磐垒主动防御 > 系统体检
      只读地逐项列出:包内文件、驱动签名状态、测试签名 / Secure Boot / HVCI、
      Minifilter 是否以正确的 Altitude 注册、驱动是否真的加载了、服务状态,
      以及由此得出的当前防护形态。

  开始菜单 > 磐垒主动防御 > 收集诊断日志
      把排查需要的东西一次性打包成桌面上的一个 zip,发出来即可。
      已自动脱敏:服务器端点、所有 API 密钥、Bearer 令牌、Windows 用户名。
      隔离区里的样本内容刻意不打包 —— 那是真实恶意样本,打包会被别的杀软拦下,
      也等于在传播样本,只给文件名和大小清单。

  (这两个入口调用的是安装目录里的 bulwark.ps1,它与便携包共用同一份文件,
   所以它结尾的个别提示语写的是便携包的用法;它打印的每一条【状态】都是从
   当前系统真实读出来的。)


■ 日志与数据位置

  %ProgramData%\Bulwark\
    install.log            安装过程记录
    bootstrap-status.txt   上次自举的人类可读记录(起不来时先看这个)
    service.log            后台服务主日志(轮转为 service.log.1)
    crash.log              崩溃记录
    rules.json             生效的规则
    audit\ history\        审计与事件历史(体积最大的两块)
    quarantine\            隔离区(真实样本,收集日志时刻意不打包)

  内核日志:DebugView,勾选 Capture Kernel。


■ 目标机上装有其他杀毒软件时

  可以共存 —— 本产品会识别已安装的第三方安全产品并主动放行,避免互相误杀。
  但【安装过程本身】可能被对方拦下:一个它不认识的程序要写 Program Files、
  注册服务、导入根证书、加载内核驱动,这在任何杀软看来都是高危动作的组合。

  遇到这种情况:在对方软件里临时允许一次,或把安装程序加入它的信任区,然后重新
  运行。安装程序是幂等的,重跑不会产生重复状态。

  本产品的签名证书是自签的,在一台没导入过它的机器上 Windows 会把安装程序显示为
  「未知发布者」,SmartScreen 也可能提示。这是自签证书的固有结果,不是文件损坏 ——
  可以用随包的 SHA256.txt 核对安装程序的哈希。


■ 静默安装(批量部署用)

  Bulwark-Setup-1.0.3.exe /VERYSILENT /NORESTART

  常用参数(Inno Setup 标准参数):
    /SILENT              只显示进度,不显示向导
    /VERYSILENT          完全静默
    /DIR="D:\Bulwark"    指定安装目录
    /NOICONS             不建开始菜单项
    /TASKS="testsigning" 顺带开启测试签名(需重启)
    /LOG="C:\setup.log"  写安装日志
    /LOG 出来的是 Inno 的日志;本产品自己的系统集成记录在
    %ProgramData%\Bulwark\install.log

    /NOSYSTEM=1          只解压文件,完全不碰系统(不装驱动、不注册服务、
                         不导入证书、不改启动设置)。给「我想先确认这个包本身
                         是对的,但还不想让它接管这台机器」的场合用。
                         这样装出来的是【没有接上的】程序文件,不具备任何防护;
                         卸载时同样加上这个开关:unins000.exe /NOSYSTEM=1

  静默卸载:
    "C:\Program Files\Bulwark\unins000.exe" /VERYSILENT
    静默模式下不会弹「是否删除数据目录」的框,按【保留】处理。


■ 情报源 API Key

  本包【不含任何 API 密钥】。情报源额度按账号计费,随包分发开发者的 Key 等于让
  所有使用者共用一份额度,几天就会被打满,然后每个人的云查都失效。

  没有 Key 也能正常运行:缺 Key 的源自动禁用并 fail-open(返回 Unknown),
  本地启发式规则、行为链检测和内核前拦截【完全不受影响】。云查只是加分项。

  要填的话,在界面「设置 > 情报源」里逐源填写即可(热更、立即生效,落在
  %ProgramData%\Bulwark\settings.json);也支持系统级环境变量
  BULWARK_VT_APIKEY / BULWARK_MB_AUTHKEY / BULWARK_OTX_APIKEY /
  BULWARK_THREATBOOK_APIKEY / BULWARK_MDC_APIKEY / BULWARK_HA_APIKEY /
  BULWARK_ABUSECH_AUTHKEY / BULWARK_AI_APIKEY
  (服务以 SYSTEM 运行,所以必须设成【系统级】环境变量,用户级它读不到)。
